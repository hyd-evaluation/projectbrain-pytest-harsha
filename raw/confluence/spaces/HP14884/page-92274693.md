# Pytest cache boundary investigation brief

**Space:** HP14884 · **Status:** current · **Version:** v1

# investigation-briefInvestigation brief

## problem-statementProblem statement

Pytest's persistent cache is intended to keep plugin and test-run state under the configured cache directory. Unexpected cache names, keys, or inspection patterns can cause filesystem activity outside that area.

The concern applies to both modification and disclosure: a cache write may create content elsewhere, while cache inspection may display information from a file that is not part of pytest's cache.

## user-visible-surfacesUser-visible surfaces

The relevant existing interfaces are:

- `config.cache.get(key, default)` for reading JSON-compatible cached values;
- `config.cache.set(key, value)` for saving JSON-compatible values;
- `config.cache.mkdir(name)` for plugin-managed cache directories;
- `pytest --cache-show [PATTERN]` for displaying matching cache entries.

The established plugin convention is to namespace cache entries using the plugin or application name to avoid clashes.

## reproduction-strategyReproduction strategy

Use an isolated temporary project and a cache directory whose parent is also controlled by the test harness.

1. Add a minimal `conftest.py` that invokes one affected cache interface during configuration.
1. Supply input that refers beyond the expected cache area.
1. Run pytest.
1. Inspect the controlled parent directory for unexpected files or directories.
1. For cache inspection, place a sentinel file outside the cache area containing a distinctive non-secret string, invoke `--cache-show` with a matching pattern, and check whether the sentinel appears in output.

Do not run this reproduction against directories containing real credentials or sensitive data.

## expected-invariantExpected invariant

All cache API filesystem effects and cache inspection results should be limited to the configured pytest cache area. Invalid or unexpected caller input should fail safely and must not modify or disclose content elsewhere.

## compatibility-considerationsCompatibility considerations

Path interpretation differs across operating systems. Investigation should include POSIX-style traversal and absolute forms and Windows-relevant rooted or drive-qualified forms. Normal namespaced plugin keys and ordinary cache usage must continue to behave as documented.

## evidence-to-captureEvidence to capture

- pytest and Python versions;
- operating system;
- configured cache directory;
- exact API surface exercised;
- sanitized input category;
- filesystem state before and after;
- command exit status, warnings, and relevant output.

## scope-boundaryScope boundary

This page documents the symptom, impact, affected interfaces, safe reproduction approach, and verification criteria only. It intentionally contains no patch design, code-change description, or information from work after the evaluation baseline.
